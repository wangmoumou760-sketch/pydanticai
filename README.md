AMT-AI-Gateway (AI智能网关 )
AMT-AI-Gateway 是由Wang开发的工业级 AI 智能中台基座。它基于 Pydantic-AI 框架，通过自研的工具调用（Tool Calling）机制，实现了大模型与企业私有数据库、工业控制系统的深度解耦与安全交互。


------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
🛡️ 核心设计方案：基于动态依赖注入的权限隔离架构
本系统在代码层面彻底解决了工业 AI 常见的“越权幻觉”问题。其核心不在于前端的菜单过滤，而在于后端 Agent 实例的物理重构。

1. 动态 Agent 工厂机制 (Dynamic Agent Factory)
系统摒弃了单例模式，采用**“一问一实例化”**的工厂模式。

代码实现：通过 async def create_dynamic_agent 函数，在接收到用户请求的瞬间，根据 User_ID 动态拉取权限清单。

依赖注入 (Deps Injection)：利用 Pydantic-AI 的 Deps 类，将经过校验的用户身份和权限集静默注入到 Agent 上下文中。这保证了在工具函数（Tool Functions）内部，可以随时进行二次安全校验（check_auth），形成双重防线。

2. 工具链物理隔离 (Physical Tool Segregation)
这是系统安全性的核心。系统在实例化 Agent 时，会对工具箱进行“物理裁剪”：

按需挂载：代码通过遍历 user_allowed_codes，仅将用户拥有权限的函数（本地或 MCP 远程）转化为 Tool 对象并填充进 tools=[] 列表。

内存级隔离：未授权的工具在当前会话的内存空间中根本不存在。由于模型无法在 tools 列表中找到未授权的函数，从底层逻辑上消除了“误调用”的可能性。

3. 语义白名单注入 (Semantic Scope Injection)
为了解决混合意图下的权限冲突，我们在代码层实现了**“白名单自描述”**技术：

Python
# 代码片段示例：
auth_summary = "、".join(set(authorized_scope)) 
system_instructions = f"你当前仅获得以下业务领域的访问权：[{auth_summary}]。"
逻辑闭环：系统在挂载工具的同时，会自动生成一份“人话版”权限清单并注入 System Prompt。

分拣协议：模型通过对比“用户需求”与“注入的白名单”，在代码指令的约束下，能够自主判断哪些子任务该执行，哪些该因“权限不足”而拒绝。

4. 权限与描述的解耦映射
系统利用数据库作为“大脑的外部存储”，通过 SQL 连表查询实现权限名与语义描述的实时对齐：

代码逻辑：get_user_permission_map 函数负责将枯燥的权限代码（perm_code）转换为模型易读的业务描述（perm_desc）。

优势：开发者可以通过 SQL 脚本直接修改 AI 的“权限认知”，无需触动任何核心推理代码，实现了业务配置与架构逻辑的深度解耦。

5. 审计层硬钩子 (Audit Hard-Hook)
在执行层，所有涉及写操作或敏感查询的工具均挂载了审计钩子：

强制溯源：无论模型如何推理，最终执行函数都会从注入的 Deps 中提取 operator_id。

不可篡改：审计记录与 AI 对话流分离，直接写入物理表 sys_operation_log，确保每一笔 AI 调用的权力使用都有据可查。

⚙️ 核心设计方案：自主调用机制与 RAG-Tools 增强架构
本网关通过 MCP (Model Context Protocol) 与 RAG-Tools (检索增强工具集) 的深度融合，实现了工业级工具调用的“高召回、低延迟、零重启”更新。

1. RAG-Tools：基于语义锚点的工具召回
针对工业领域中私有数据项（如施工号、流水号）与通用工具命名的冲突，我们设计了 RAG-Tools 语义锚点技术：

语义加固 (Semantic Fortification)：系统不再仅仅依赖工具名称（如 get_rail_data）进行匹配，而是通过数据库层的 perm_desc 字段，为每个工具注入包含“业务场景 + 关键词触发 + 预期输出”的语义锚点。

向量空间权重干预：通过在描述中强行嵌入 【生产-核心】 等高权重标签，改变 Embedding 向量的分布，确保 AI 在处理模糊意图时，私有业务工具的召回优先级高于通用逻辑。

2. 万能 MCP 代理转发 (Universal MCP Proxy)
为了实现大模型与底层业务系统的深度解耦，系统构建了基于 SSE 协议的 万能转发适配器：

代码架构设计：采用 make_mcp_wrapper 工厂函数。它作为一个高度抽象的“壳”，能够将模型生成的任何 JSON 参数透明地转发至远程 MCP Server（10.44.209.95）。

动态参数映射：利用 Python 的 **kwargs 承接能力，网关无需预先定义每个工具的具体参数结构，模型根据 RAG 注入的 __doc__ 描述自动提取参数，实现了“协议层对等转换”。

3. 敏捷扩展与“零重启”更新逻辑
系统实现了工具链路的“热插拔”设计，大幅降低了运维成本：

敏捷发布链路：

MCP 端：新增函数并重启远程 MCP 服务。

网关端：在 sys_permissions 数据库中录入对应的 perm_code。

无感更新机制：由于 create_dynamic_agent 在每次对话请求时都会重新扫描数据库并执行 dynamic_tools.append，新功能无需重启网关主程序即可瞬间上线。这保证了在生产环境不中断的情况下，实现能力的平滑扩容。

4. 本地化执行与快速响应
除了远程 MCP 工具，系统还保留了高性能的 Local Tool 调用栈：

本地化加速：针对高频、低延迟要求的操作（如用户信息查询、审计日志写入、本地硬件控制），直接在 LOCAL_TOOLS_MAP 中定义 Python 原生函数。

混合调用编排：Agent 在单次推理中，可以根据任务复杂度，自动编排“本地查询 -> 远程 MCP 写入 -> 本地日志记录”的连招组合，响应时间控制在毫秒级。

5. 状态机反馈与 SSE 异步推送
为解决工业逻辑调用链路长的问题，系统在 main.py 层面实现了 流式状态感知：

思考过程透明化：通过自定义的 status 报文，将 AI 正在“尝试调用某工具”或“等待 MCP 返回”的中间状态实时推送到前端。

异步非阻塞：基于 FastAPI 的异步特性，确保在高并发环境下，多个用户的工具调用请求不会相互阻塞。

🛡️ 核心设计方案：工业级安全红线与全链路审计 (Safety Rails & Audit Traceability)
在工业自动化场景中，AI 不仅仅是“聊天机器人”，更是“指令发起者”。本网关通过**“代码硬钩子”与“身份令牌追踪”**，为 AI 的每一次工具调用构建了闭环安全审计体系。

1. 身份锚定与权限双检 (Dual-Verification)
系统在代码层实现了**“身份随行”**机制，确保 AI 无法脱离用户权限运行：

Deps 依赖锁定：通过 Pydantic-AI 的 Deps 机制，操作员的 Employee_ID 被硬编码进 Agent 的生存周期。

二次安检 (Internal Check)：即便模型因幻觉试图调用未挂载的工具，工具函数内部的 check_auth 钩子会利用注入的 Deps 进行二次实时校验。如果权限不符，函数将直接截断执行并返回“拒绝访问”，形成**“初始化挂载 + 执行前校验”**的双保险。

2. 旁路审计日志 (Sidecar Audit Logging)
为了保证审计的真实性，系统设计了独立于对话流的**“旁路记录器”**：

全维度采集：sys_operation_log 不仅记录结果，更强制记录 Raw_Params (AI 生成的原始参数)。这对于排查“模型幻觉导致误操作”至关重要，运维人员可以复现模型在执行那一刻的逻辑。

执行快照：日志系统会捕获工具返回的原始数据快照，确保即便底层数据库发生变化，当时的执行现场也能被完整还原。

3. 静默调用协议与输出脱敏 (Silent Protocol & Masking)
针对工业安全需求，系统在 System Prompt 逻辑层实施了**“静默协议”**：

黑盒执行：严禁 AI 向前端输出任何技术细节（如 SQL 片段、MCP 路由地址或 JSON 参数）。这不仅是为了界面美观，更是为了防止攻击者通过对话引导诱骗出底层架构信息。

语义重塑：所有工具返回的原始错误信息会经过一层“语义脱敏”，转化为对用户友好的业务提示，避免暴露数据库结构或敏感字段名。

4. 动态安全红线 (Dynamic Safety Redlines)
针对高危操作（如权限变更、硬件复位），系统设置了**“职级压制”**逻辑：

Admin > Dev > User：在 manage_system_auth 等工具中，系统会实时计算操作者与目标对象的“职级权重”。

逻辑死锁：代码层面严禁“自己给自己加戏”。通过 if op_id == target_id: return "拒绝" 这一行硬代码，彻底杜绝了通过 AI 进行提权的逻辑漏洞。

5. 跨设备记忆持久化 (Session Persistence)
系统利用 MySQL 实现了类似 Dify 的长对话记忆管理：

上下文一致性：通过 conversation_id 绑定，确保 AI 在多步复杂推理（如：查人 -> 找单号 -> 执行核销）中不会丢失上下文。

分布式安全：由于记忆存储在服务端数据库而非客户端缓存，确保了多终端接入（如 PDA 扫码枪、PC 终端）时，权限与状态的绝对同步。

🛠️ 快速开始 (Quick Start)
1. 环境准备
确保你的本地或服务器环境满足以下要求：

Python: 3.10+

数据库: 拥有 Oracle (业务数据) 与 MySQL (系统审计) 的访问权限。

模型后端: Ollama 或远程 OpenAI 兼容接口（推荐使用 Qwen2.5-7B/72B-Instruct）。

2. 依赖安装
Bash
# 创建虚拟环境
python -m venv .venv
source .venv/bin/activate  # Linux/Mac
# .venv\Scripts\activate  # Windows

# 安装核心依赖
pip install fastapi uvicorn pydantic-ai sqlalchemy pymysql mcp
3. 核心配置 (.env)
在项目根目录创建 .env 文件，配置数据库与模型映射地址：

代码段
# 数据库配置
ORACLE_URL=oracle+cx_oracle://user:pass@x.x.x.x:1521/service_name
MYSQL_URL=mysql+pymysql://user:pass@localhost:xxxx/amt_ai_gateway

# MCP 远程节点
MCP_SERVER_URL=

# 模型配置
MODEL_PROVIDER=ollama  # 或 openai
MODEL_ID=yasserrmd/Qwen2.5-7B-Instruct-1M
4. 启动网关
Bash
# 启动 FastAPI 服务
python main.py
服务启动后，默认 API 文档地址为：http://localhost:8000/docs。
